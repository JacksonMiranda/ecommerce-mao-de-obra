# Contribuindo para o E-commerce de Mão de Obra / Contributing to Labor E-commerce

[English version below](#english)

## 🇧🇷 Português

Obrigado por seu interesse em contribuir com o projeto! Valorizamos todas as contribuições, desde correções de bugs até novas funcionalidades.

### Como Contribuir

1. **Fork o repositório**
2. **Clone seu fork**: `git clone https://github.com/SEU_USUARIO/ecommerce-mao-de-obra.git`
3. **Crie uma branch para sua feature**: `git checkout -b feature/nova-funcionalidade`
4. **Faça suas alterações**
5. **Execute os testes**: `npm test`
6. **Execute o linter**: `npm run lint`
7. **Commit suas mudanças**: `git commit -m "feat: adiciona nova funcionalidade"`
8. **Push para sua branch**: `git push origin feature/nova-funcionalidade`
9. **Abra um Pull Request**

### Padrões de Commit

Utilizamos [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` nova funcionalidade
- `fix:` correção de bug
- `docs:` alterações na documentação
- `style:` formatação, lint fixes
- `refactor:` refatoração de código
- `test:` adição ou correção de testes
- `chore:` mudanças de build, ferramentas auxiliares

### Código de Conduta

Por favor, leia nosso [Código de Conduta](CODE_OF_CONDUCT.md) antes de contribuir.

### Reportando Bugs

- Use os templates de issue disponíveis
- Inclua informações sobre seu ambiente (navegador, OS)
- Descreva os passos para reproduzir o problema
- Inclua screenshots se aplicável

### Sugerindo Funcionalidades

- Use o template de feature request
- Explique o problema que a funcionalidade resolve
- Descreva a solução proposta
- Considere alternativas

## 🇺🇸 English

Thank you for your interest in contributing to the project! We value all contributions, from bug fixes to new features.

### How to Contribute

1. **Fork the repository**
2. **Clone your fork**: `git clone https://github.com/YOUR_USERNAME/ecommerce-mao-de-obra.git`
3. **Create a feature branch**: `git checkout -b feature/new-feature`
4. **Make your changes**
5. **Run tests**: `npm test`
6. **Run linter**: `npm run lint`
7. **Commit your changes**: `git commit -m "feat: add new feature"`
8. **Push to your branch**: `git push origin feature/new-feature`
9. **Open a Pull Request**

### Commit Standards

We use [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` new feature
- `fix:` bug fix
- `docs:` documentation changes
- `style:` formatting, lint fixes
- `refactor:` code refactoring
- `test:` adding or fixing tests
- `chore:` build changes, auxiliary tools

### Code of Conduct

Please read our [Code of Conduct](CODE_OF_CONDUCT.md) before contributing.

### Reporting Bugs

- Use available issue templates
- Include information about your environment (browser, OS)
- Describe steps to reproduce the problem
- Include screenshots if applicable

### Suggesting Features

- Use the feature request template
- Explain the problem the feature solves
- Describe the proposed solution
- Consider alternatives
